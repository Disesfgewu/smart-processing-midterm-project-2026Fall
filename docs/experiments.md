# 測試實驗規劃

對應題目功能要求 5 與繳交內容 3、4（提示詞比較、失敗案例分析）。**以下為規劃，尚未執行，所有假設都待驗證。**

## 背景觀察

- 一般性高的影像（例如 COCO 的貓、遙控器）在 WSL baseline（OWL-ViT + MobileSAM）上效果良好。
- 預期工業場景較困難：相似零件（螺絲／螺帽／墊片）、小物件、反光金屬、遮擋與堆疊。
- OWL 的文字編碼器為 CLIP 系，學到的是「視覺概念」而非專有名詞：型號、行話、特定人物名稱不一定有效。
- OWL-ViT 文字長度上限 16 token（含首尾特殊 token，約 12 個字）；超過會造成索引錯誤。已實測 27 token 的描述超限。
- 此系統不用於辨識特定人物身分；特定人名不屬於可行的提示。

## 實驗一：提示詞寫法比較（功能要求 5）

固定同一批影像（≥10 張，含工業場景）與同一組標註，比較偵測正確率：

| 組別 | 說明 | 例 |
|---|---|---|
| A. 型號／行話式 | 專有名詞 | `M4 hex nut` |
| B. 類別式 | 通用類別 | `a nut` |
| C. 描述式 | 外觀屬性（短） | `a small hexagonal metal nut` |
| D. HyDE 多描述取最高分 | 見下 | 3~5 個描述一起查詢 |
| E. HyDE 多描述加投票 | 見下 | 至少 2 個描述在同位置偵測才保留 |

評估指標：偵測數量是否正確（計數誤差）、框與標註的 IoU、遮罩面積誤差、誤報／漏報數。

## 實驗二：HyDE 風格的提示擴展

**構想**：用 LLM 將原始提示改寫成數個「可能相似」的短外觀描述，系統以全部描述查詢，同一物件取信心最高者並歸併回原始概念。

```
"M4 hex nut" → LLM 生成 3~5 個 ≤12 字的外觀描述
            → 全部丟入 OWL 作為查詢
            → 同一物件取最高分描述，標籤歸併回 "M4 hex nut"
```

- OWL 對每個位置本來就取所有查詢中的最高分，因此「取最高」為現成行為，需新增的是標籤歸併（避免 count／area 被拆成多份）。
- LLM 只在「換提示」時呼叫一次，不影響逐幀 FPS。

**已知風險（需要用實驗驗證）**
1. 不同描述的分數不可直接比較：越籠統的描述（`a metal object`）分數通常越高，可能搶走正確描述。
2. LLM 可能生成不貼切的描述，把背景或其他零件當成目標。
3. 描述必須 ≤16 token。
4. 此方法解決「詞彙」問題，不解決「身分」問題（`某某教授` → `a man in glasses` 只會找到所有戴眼鏡的人）。

**緩解方式（可作為 D、E 組別的變數）**：各描述各自門檻、投票（≥2 描述一致）、限制描述數量（3~5）。

**部署考量**：Jetson 離線時需小型本地 LLM 或預先產生的查表；WSL 開發階段可使用 API。需在報告中說明取捨。

## 實驗三：失敗案例分析（繳交內容 4）

收集至少 5 張截圖（含製造現場與失敗案例），依下列類型歸納原因與提示詞設計原則：

- 相似物件被混淆
- 小物件漏偵測（OWL-ViT 輸入大小限制）
- 遮擋／堆疊造成遮罩不完整
- 反光或低對比造成邊界錯誤
- 同一物件被重複偵測（目前已觀察到，count 偏高，大框包小框時 NMS IoU 0.5 無法去除）
