# 製造現場應用情境與測試素材

對應功能要求 3（至少 1 個製造現場情境、可執行中更換提示）與繳交內容 4（至少 5 張截圖含失敗案例）。

## 已實作的情境：零件齊套檢查（kitting verification）

**流程**：作業員把一個工單所需的零件放進料盤 → 用文字指定零件 → 系統計數並與預期數量比對 → 顯示 PASS / FAIL。

- 在網頁「製造情境：數量檢查」面板輸入每種零件（提示詞）的預期數量，即時顯示 `OK`、`NG（缺 n）`、`NG（多 n）`，全部符合才是 PASS。
- 換工單 / 換產品時**只改提示詞與預期數量，不需重新訓練、不需重啟**——這正是開放詞彙模型相對於傳統偵測器的價值。
- 同時顯示各零件的遮罩面積（`遮罩面積` 欄位），可延伸為「塗膠面積」「料盤填滿率」。
- 影片模式會產生各零件數量隨時間變化的曲線與 CSV，可用來看輸送帶上的通過數量。
- 支援圖片、影片檔、瀏覽器攝影機、伺服器端攝影機／影片路徑（Jetson 接 USB / CSI 攝影機用）。

### 可延伸的變化（擇一做深即可）

| 情境 | 提示詞例 | 指標 |
|---|---|---|
| 零件齊套（已實作） | `a screw`、`a nut`、`a washer` | 各零件數量 vs 預期 |
| 缺料 / 漏裝 | 空位 `an empty slot` | 數量 |
| 面積 / 佔比 | `a glue area`、`a solder joint` | 遮罩面積、遮罩/框比例 |
| 依顏色分類計數 | `a red cap`、`a blue cap` | 各顏色數量 |
| 換線展示 | 執行中把 `a screw` 換成 `a washer` | 免重訓、免重啟 |

## 找不到好圖片時

**最推薦：自己拍**。題目本來就要求「自行拍攝或選用至少 10 張影像」，而且最終 Demo 是即時攝影機畫面，自己的素材最能代表實際效果。

拍攝建議：
- 素色背景（白紙、木板、黑布）+ 均勻光源（避免強反光與陰影）；手機垂直俯拍、距離 20~40 cm。
- 一張圖放 3~4 種零件（螺絲、螺帽、墊片、彈簧、電阻、LED、杜邦線端子、瓶蓋、積木都可以），每種 2~8 個。
- 刻意拍出困難情況，作為失敗案例分析的素材：相似零件混放（螺帽 vs 墊片）、小零件、零件互相遮擋 / 堆疊、金屬反光、不同光線。
- 每張圖記下「各零件實際數量」（人工計數），作為正確率的標準答案；至少 10 張，並用 ≥3 種提示詞寫法重跑。

公開資料集（授權請自行再確認後使用）：
- [MVTec Screws](https://www.mvtec.com/company/research/datasets/mvtec-screws)：384 張、13 種螺絲與螺帽、木質背景，另有標註框與類別；授權為 CC BY-NC-SA 4.0（非商業，課程專題屬於合理範圍，報告中需標註來源）。
- [Roboflow Universe](https://universe.roboflow.com/) 上的 nut / bolt / washer / screw 資料集（例如 NutsNBolts、screws-workspace、screw-gpokz）：授權依各專案而定，請在專案頁面確認；影像數量較少。
- [MVTec AD](https://www.mvtec.com/company/research/datasets/mvtec-ad)：15 類工業物件與紋理（金屬螺帽、電晶體、藥丸等）的缺陷檢測資料集，同為非商業授權；偏向缺陷偵測，不是計數用。

製造影片（Demo、影片模式用）：自己用手機錄一段「手把零件放進料盤」或「零件在桌面滑過」最直接；也可在有明確授權的免費影片網站搜尋 factory / assembly line / conveyor 類素材。影片請用 H.264 mp4 或 webm（瀏覽器才播得出來）。

## 評估方式（接功能要求 5）

1. 建立 `data/eval/`，每張圖一列標準答案（零件 → 實際數量）。
2. 每張圖用 ≥3 種提示詞寫法（類別式 / 描述式 / 型號式，見 [experiments.md](experiments.md)）各跑一次。
3. 指標：**計數正確率**（偵測數量 == 標準答案的比例）、**計數誤差**（平均絕對誤差）、失敗類型（缺偵測 / 多偵測 / 混淆）。
4. 批次評估腳本尚未實作（見 experiments.md 待辦）。

## 已知限制（會影響計數，須在報告中說明）

- 同一物件可能被 OWL 重複偵測（大框包小框，NMS IoU 0.5 不一定去得掉），會讓 count 偏高；目前只能靠提高 threshold 緩解，尚未做根本處理。
- 小零件（OWL-ViT 輸入 768×768）與堆疊 / 遮擋的零件容易漏偵測。
- 開放詞彙模型對型號、行話不穩定，建議用外觀描述（見 experiments.md）。
