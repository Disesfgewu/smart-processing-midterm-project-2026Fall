# 製造現場應用情境與測試素材

對應功能要求 3（至少 1 個製造現場情境、可執行中更換提示）與繳交內容 4（至少 5 張截圖含失敗案例）。

## 已實作的情境：零件檢查（工單 → 數量 / 面積 → OK·NG → 紀錄 → 報表）

作業員把一個工單所需的零件放進料盤或經過輸送帶 → 用文字指定零件 → 系統計數、量面積並與工單比對 → 判定 PASS / FAIL → 留下紀錄與報表。
換工單 / 換產品時**只改提示詞與預期值，不需重新訓練、不需重啟**——這正是開放詞彙模型相對於傳統偵測器的價值。

網頁「製造情境：零件檢查」卡片（位於結果圖下方）：

| 功能 | 說明 |
|---|---|
| **工單** | 內建 3 個範本（螺絲包、電子零件盤、貓與遙控器測試用），也可把目前的提示詞與預期值存成自己的工單（存在這個瀏覽器的 localStorage）。套用工單會一次填好提示詞與預期值 |
| **預期數量** | 每種零件設定預期數量，顯示 `OK`、`NG（缺 n）`、`NG（多 n）` |
| **面積換算（mm²）** | 手動輸入比例尺（mm/像素），或在影像上**點兩個已知實際距離的點**校準。畫面標籤、統計表都會顯示 mm²；畫面縮放時自動換算 |
| **單件面積範圍** | 每種零件可設下限 / 上限（mm²），**超出範圍判 NG**，用來抓錯件或破損。未校準或沒計算遮罩時顯示「無法判定」，**不會假裝 PASS** |
| **整體判定** | PASS / FAIL / 無法判定 / 未設定 |
| **檢查紀錄** | 手動「記錄目前結果」，或勾選「結果改變時自動記錄」（判定或數量改變才記，不是每幀都記，適合輸送帶 / 影片）；紀錄含當時的畫面縮圖 |
| **匯出** | 「下載檢查紀錄 CSV」（每筆的各零件數量 / 預期 / 合計面積 / 判定）；「**產生報表**」開啟可列印的報表（見下） |

**報表內容**：基本資訊（工單、期間、偵測設定、比例尺）→ 總覽（筆數、PASS / FAIL、合格率）→ **各零件統計**（預期數量、偵測數量平均 / 最小 / 最大、數量符合率、單件面積平均 / 最小 / 最大與樣本數、設定的面積範圍）→ 逐筆明細（含失敗案例的畫面截圖，FAIL 最多 50 張、其餘最多 10 張）。
數量符合率以「每一筆紀錄當時的預期值」計算（預期值中途改過也正確）。

支援圖片、影片檔、瀏覽器攝影機、伺服器端攝影機 / 影片路徑（Jetson 接 USB / CSI 攝影機用）。

**限制**：
- 面積由 SAM 遮罩像素數乘以比例尺平方換算，**假設鏡頭垂直拍攝平面**；有透視或鏡頭畸變時不準，需要實測驗證。
- 伺服器串流模式的畫面上只疊「數量 OK / NG」；面積範圍的判定與紀錄在瀏覽器端計算（串流模式要手動輸入比例尺，不能點兩點校準）。
- 工單存在瀏覽器本機，換瀏覽器或清除網站資料就沒了。

### 可延伸的變化（擇一做深即可）

| 情境 | 提示詞例 | 指標 |
|---|---|---|
| 零件齊套（已實作） | `a screw`、`a nut`、`a washer` | 各零件數量 vs 預期 |
| 缺料 / 漏裝 | 空位 `an empty slot` | 數量 |
| 面積 / 佔比 | `a glue area`、`a solder joint` | 遮罩面積、遮罩/框比例 |
| 依顏色分類計數 | `a red cap`、`a blue cap` | 各顏色數量 |
| 換線展示 | 執行中把 `a screw` 換成 `a washer` | 免重訓、免重啟 |

## 找不到好圖片時

**最推薦：自己拍**。題目本來就要求「自行拍攝或選用至少 10 張影像」，而且最終 Demo 是即時攝影機畫面，自己的素材最能代表實際效果。

拍攝建議：
- 素色背景（白紙、木板、黑布）+ 均勻光源（避免強反光與陰影）；手機垂直俯拍、距離 20~40 cm。
- 一張圖放 3~4 種零件（螺絲、螺帽、墊片、彈簧、電阻、LED、杜邦線端子、瓶蓋、積木都可以），每種 2~8 個。
- 刻意拍出困難情況，作為失敗案例分析的素材：相似零件混放（螺帽 vs 墊片）、小零件、零件互相遮擋 / 堆疊、金屬反光、不同光線。
- 每張圖記下「各零件實際數量」（人工計數），作為正確率的標準答案；至少 10 張，並用 ≥3 種提示詞寫法重跑。

公開資料集（授權請自行再確認後使用）：
- [MVTec Screws](https://www.mvtec.com/company/research/datasets/mvtec-screws)：384 張、13 種螺絲與螺帽、木質背景，另有標註框與類別；授權為 CC BY-NC-SA 4.0（非商業，課程專題屬於合理範圍，報告中需標註來源）。
- [Roboflow Universe](https://universe.roboflow.com/) 上的 nut / bolt / washer / screw 資料集（例如 NutsNBolts、screws-workspace、screw-gpokz）：授權依各專案而定，請在專案頁面確認；影像數量較少。
- [MVTec AD](https://www.mvtec.com/company/research/datasets/mvtec-ad)：15 類工業物件與紋理（金屬螺帽、電晶體、藥丸等）的缺陷檢測資料集，同為非商業授權；偏向缺陷偵測，不是計數用。

製造影片（Demo、影片模式用）：**自己錄最直接**——用手機固定拍攝，白紙或黑布當「輸送帶」，把零件放在紙上緩慢拉過鏡頭，或手把零件放進料盤。
影片請用 H.264 mp4 或 webm（瀏覽器才播得出來）。其他來源（以下均為搜尋結果的摘要，**授權與內容請在各頁面確認**，我沒有驗證個別影片）：
- 學術：[Iron ore 輸送帶影像資料集（Mendeley Data）](https://data.mendeley.com/datasets/s25x2bnshz)（輸送帶異物與異常、YOLO 標註，非零件計數；授權請看資料集頁）；[LEGO 積木輸送帶影片資料集（格但斯克工業大學）](https://pub.pg.edu.pl/en/publication/158283/video-of-lego-bricks-on-conveyor-belt-dataset-series)（手機 Full HD、白色輸送帶，偏分類；授權請看頁面）。
- 教學：[Roboflow：用電腦視覺計算輸送帶上的物件](https://blog.roboflow.com/counting-objects-conveyor-belt/)（螺栓螺帽計數的做法，不是資料集）。
- 免費影片素材站：[Pexels](https://help.pexels.com/hc/en-us/articles/360042295214-Can-I-use-the-photos-and-videos-for-a-commercial-project)、Pixabay、[Coverr](https://coverr.co/stock-video-footage/conveyor-belt)、[Mixkit 製造類](https://mixkit.co/free-stock-video/manufacturing)——搜尋 factory / assembly line / conveyor；注意畫面中的商標、品牌、人臉可能另有權利限制，且多為宣傳風格的運鏡，不一定適合計數。

## 評估方式（接功能要求 5）

1. 建立 `data/eval/`，每張圖一列標準答案（零件 → 實際數量）。
2. 每張圖用 ≥3 種提示詞寫法（類別式 / 描述式 / 型號式，見 [experiments.md](experiments.md)）各跑一次。
3. 指標：**計數正確率**（偵測數量 == 標準答案的比例）、**計數誤差**（平均絕對誤差）、失敗類型（缺偵測 / 多偵測 / 混淆）。
4. 批次評估腳本尚未實作（見 experiments.md 待辦）。

## 已知限制（會影響計數，須在報告中說明）

- 計數偏高（局部／巢狀偵測）：實測（貓 2 隻、31 個影格、'a cat'）預設門檻 0.1 時，不用 NMS 有 26% 的影格多報，用 IoU-NMS（0.5）仍有 23%（7/31 數出 3 隻）；多出的框分數僅 0.11~0.13，面積約佔畫面 8~9%，其 91~94% 落在真實貓框內但 IoU 只有 0.18——是貓身上的局部被當成另一隻，IoU-NMS 抓不到。提高門檻到 0.2 可消除（本例）；模擬「包含抑制」（丟棄大部分面積落在更高分框內的低分框）在門檻 0.1 把多報降到 0%、漏報 0%。
  僅單一場景、31 幀幾乎相同的影格、兩隻貓不互相巢狀，不能推論到工業零件；真正巢狀的同類物件（例如大盤子裡的小盤子）可能被誤殺，需用真實素材驗證。
- 小零件（OWL-ViT 輸入 768×768）與堆疊 / 遮擋的零件容易漏偵測。
- 開放詞彙模型對型號、行話不穩定，建議用外觀描述（見 experiments.md）。
